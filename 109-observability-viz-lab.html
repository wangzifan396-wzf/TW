可观测性 可视化实验室

MODULE 02

Metrics 类型：Counter / Gauge / Histogram / Summary

四种核心指标类型的采集与聚合形态。Counter 单调递增、Gauge 自由波动、Histogram 分桶统计分布、Summary 计算分位数。切换类型观察实时形态。

metric-types.svg

Counter

Counter 只增不减（除非重启归零），适合请求数、错误数等累计量。PromQL 用 rate() 计算速率。

MODULE 03

结构化日志聚合

JSON 结构化日志便于聚合检索。下方为日志流，可按级别过滤、全文检索。结构化字段使日志可被索引、关联 Trace ID 并驱动告警。

log-aggregation.log

日志聚合

结构化日志把每条记录编码为 JSON，字段如 trace_id、level、service 可被 Loki / Elasticsearch 索引。全文检索匹配消息体，级别过滤快速定位 ERROR，trace_id 可反向跳转到追踪系统。

MODULE 04

OpenTelemetry 统一遥测

OpenTelemetry 用统一 API/SDK 生成 Traces、Metrics、Logs 三支柱遥测数据，经 Collector 处理后导出到任意后端。播放观察一次请求同时产出三类信号。

otel-pipeline.svg
Trace Metric Log Collector

三支柱统一

OpenTelemetry 用同一个 context（trace context / baggage）把三支柱关联起来：一条 Span、若干 Metric 数据点、若干 Log 记录共享同一 trace_id，可在后端交叉跳转。切换支柱高亮对应数据流。

MODULE 05

采样策略：头部 vs 尾部

头部采样在 Trace 开始时按概率决定，简单但可能丢弃有价值的事故；尾部采样在 Trace 完成后根据错误/延迟等规则决策，能保留关键链路。拖动滑块调节采样率。

sampling.svg
采样保留 丢弃 错误链路 慢链路

采样对比

头部采样对每个 Trace 独立掷骰，错误链路同样可能被丢弃；尾部采样在 Span 全部到达后决策，可优先保留含错误或高延迟的 Trace，显著提升事故可观测性。

MODULE 07

异常检测与 SLO / 错误预算

基于时间序列的异常识别，叠加 SLO 与错误预算消耗。调节阈值观察检测灵敏度，播放生成新数据并注入异常点。

anomaly-slo.svg
指标序列 SLO 阈值 异常点 错误预算

异常检测 + 错误预算

SLO 定义目标可靠性（如 99.9%），错误预算 = 1 − SLO。当实际错误率消耗预算过快（burn rate 高）即触发告警。异常检测在序列偏离基线（均值 ± 阈值×σ）时标记。

MODULE 08

告警策略：降噪 / 聚合 / 升级

多级告警（P0-P3）经去重、聚合、抑制降噪后路由。模拟告警风暴观察分组如何压缩通知量，超时未确认则升级到下一级值班人。

alert-policy.svg
P0 致命 P1 严重 P2 警告 聚合通知

告警生命周期

原始告警进入路由后：①去重（相同标签合并）②聚合（同服务同时间窗合并）③抑制（高级别抑制低级别）④分组通知。未在 ack 超时内确认则升级。点击“触发风暴”观察降噪效果。
