MODULE 02

BeyondCorp 信任评估

设备、用户、上下文三维信任。Google BeyondCorp 不基于网络位置授权，而是综合三维信号实时计算信任分数，决定放行、拒绝或二次认证。

beyondcorp-trust.svg
设备信任 用户信任 上下文信任

访问决策

调整三个滑块模拟不同的设备/用户/上下文状态。综合分数 ≥ 80 直接放行；50–79 触发 Step-up 二次认证；< 50 拒绝访问。

MODULE 03

mTLS 双向认证握手

双向 TLS 中客户端与服务端互相验证证书。基于 PKI 证书链（Root CA → Intermediate → Leaf），双方在握手阶段交换并校验证书，建立加密通道。

mtls-handshake.svg
客户端 服务端 证书链 密钥协商

握手步骤

点击“单步”逐步执行 mTLS 握手。双方交换 Hello、各自发送证书与 CertificateVerify，最终协商出共享密钥，建立加密通道。

MODULE 06

微分段与东西向流量

微分段将网络切分为细粒度安全区域，控制东西向（服务间）流量。即使攻击者突破边界，横向移动也被严格限制。切换分段开关对比效果。

micro-segmentation.svg
放行流量 阻断流量 分段边界 攻击者

横向移动分析

开启微分段后，攻击者从 Web 服务突破，无法横向访问 DB 与 Auth 服务。关闭后，东西向流量自由流动，攻击可级联蔓延。

MODULE 07

持续信任评估

零信任不是一次性认证，而是持续评估。设备状态、行为模式、地理位置等信号实时更新风险分数。分数跌落阈值即触发再认证或撤销会话。

continuous-risk.svg
高信任 中信任 低信任 风险事件

实时风险评分

点击“播放”模拟一段时间内的信任分数变化。登录提升分数；异常登录、设备失合规、空闲过久等事件降低分数；MFA 通过则回升。

MODULE 08

VPN vs ZTNA 对比

传统 VPN 授予网络级访问，用户接入即获整个子网可达；零信任网络访问（ZTNA）按应用最小授权，默认隐藏。切换模式对比访问范围与攻击面。

vpn-vs-ztna.svg
用户 网关/代理 可达应用 暴露面

访问模式对比

VPN 模式：用户接入后整个内网可达，横向移动风险大。ZTNA 模式：Broker 仅代理被授权的单个应用，其余应用对用户不可见，攻击面最小化。
