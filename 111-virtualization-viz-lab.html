MODULE 03

内存虚拟化：EPT 与影子页表

Guest 虚拟地址（GVA）→ Guest 物理地址（GPA）→ Host 物理地址（HPA）。影子页表（SPT）软件合并两层；EPT 硬件完成 GPA→HPA 翻译。切换模式观察查表过程。

ept-shadow-pt.svg
Guest 页表 (GVA→GPA) EPT (GPA→HPA) 影子页表 (GVA→HPA) 地址翻译步

翻译机制

影子页表（SPT）由 VMM 维护，直接映射 GVA→HPA，guest 透明但 shadow fault 开销大；EPT 是硬件页表，GPA→HPA 由 MMU 走 EPT，结合 VPID 减少 TLB 冲刷，性能更优。

MODULE 04

容器 vs 虚拟机

VM 通过 Hypervisor 提供完整硬件级隔离，每个 guest 自带内核；容器共享宿主内核，通过 namespace/cgroup 实现轻量隔离。切换指标对比启动时间、资源开销与隔离强度。

container-vs-vm.svg
VM 栈 容器栈 共享内核 Guest 内核

对比维度

VM 启动需引导整个 guest 内核（秒级），内存开销大但隔离强；容器复用宿主内核（毫秒级启动），密度高但共享内核带来逃逸风险。强隔离场景选 VM，高密度场景选容器。

cgroup 资源限制

cgroup 以层级树组织进程并施加资源限制。CPU/Memory/IO 控制器分配配额。调整滑块改变 cgroup-A 的 CPU 与内存上限，观察子组抢占与 OOM 行为。

cgroups.svg
cgroup 节点 进程 CPU 配额 内存上限

cgroup v2 说明

cgroup v2 统一层级，进程只能附属于单一 cgroup。CPU 通过 cpu.max 限制配额；内存通过 memory.max 触发 OOM 或回收；IO 通过 io.max 限制带宽。子组配额不能超过父组。

MODULE 08

安全沙箱：gVisor vs Kata

普通容器直接 syscall 到宿主内核；gVisor 在用户态实现 Sentry 拦截 syscall；Kata 为每个容器起轻量 VM + 独立内核。切换方案观察隔离边界与性能权衡。

sandbox-gvisor-kata.svg
应用 Sentry / Guest 内核 Host 内核 攻击面

沙箱方案对比

普通容器攻击面=宿主内核全部 syscall；gVisor 仅暴露 ~60% 安全实现的 syscall，性能损失约 10-30%；Kata 用 QEMU/Firecracker 起 VM，隔离最强但启动慢、内存开销大。多租户场景优先 Kata/gVisor。
