01

RAG 全流程架构

Query → Embed → Retrieve → Rerank → Generate。用户提问经过 Embedding 后在向量库中检索 Top-K，重排序后组装上下文，最终由 LLM 生成带引用的回答。

02

文档分块策略

Fixed-size 固定大小、Sentence 句子分割、Semantic 语义分块三种策略对比。分块大小直接影响检索精度。

03

Embedding 嵌入空间

文本如何变为向量。Token → Embedding 向量 → 高维空间中的点。相似文本在空间中距离更近。

04

向量检索算法

Brute-Force 暴力搜索、IVF 倒排索引、HNSW 层级导航小世界图三种检索算法对比。

05

重排序 (Reranking)

Bi-Encoder 双塔召回 vs Cross-Encoder 交叉编码精排。两阶段检索：先快召回 Top-K，再精排 Top-N。

06

上下文窗口管理

Token 预算分配：System Prompt + Retrieved Context + User Query + Response。上下文顺序影响生成质量。

07

生成与引用

LLM 如何利用检索到的上下文生成回答，并标注信息来源。Citation 引用链路可视化。

08

RAG 评估指标

Faithfulness 忠实度、Answer Relevance 答案相关性、Context Precision 上下文精确度、Context Recall 上下文召回率。RAGAS 框架核心指标。
