MODULE 01

SBOM 软件物料清单

SBOM（Software Bill of Materials）枚举组件与依赖关系。CycloneDX 与 SPDX 是两大标准格式。点击依赖树节点查看组件元数据与传递依赖。

组件详情

点击依赖树中的任一组件查看其 SBOM 元数据：名称、版本、许可证、来源与已知漏洞状态。

MODULE 02

SLSA 供应链等级框架

SLSA（Supply-chain Levels for Software Artifacts）分为 L1–L4 四级，逐级强化 Source、Build、Provenance 要求。点击各级查看其安全控制项。

slsa-levels.svg
L1 基线 L2 可信构建 L3 硬化平台 L4 双人审核

SLSA 等级说明

点击各级别查看 Source / Build / Provenance 三大维度的具体要求。等级越高，构建过程越难以篡改，来源证明越完整。

MODULE 04

可重现构建与哈希验证

可重现构建（Reproducible Build）要求同一源码在不同环境产出比特一致的制品。对比两次构建的哈希，逐字节验证完整性。

reproducible-build.svg
哈希一致 哈希差异 构建 A 构建 B

构建对比

点击“运行构建”模拟两次独立构建。可重现时哈希完全一致；引入非确定性因素（时间戳、路径、随机种子）则产生差异。

MODULE 05

Sigstore 镜像签名

Sigstore / Cosign 为制品签名，并写入 Rekor 透明日志。验证时同时校验签名与日志包含性，确保证制品来源可审计、不可抵赖。

sigstore-signing.svg
制品 签名 透明日志 验证

签名与验证流程

点击“签名”逐步执行：Fulcio 颁发短时证书 → Cosign 用私钥签名 → Rekor 记录到透明日志。验证方校验签名有效且日志可查。

MODULE 06

依赖混淆与 Typosquatting

攻击者注册与内部包同名或拼写相近的恶意包（Typosquatting），诱导开发者误装。对比包名，识别混淆攻击。

typosquatting-detect.svg
合法包 恶意混淆包 可疑 内部包

混淆检测

点击任一候选包查看其与目标包的编辑距离、注册时间、下载量。编辑距离小、注册晚、下载低 = 高风险混淆。
